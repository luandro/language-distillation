# Design: Dictionary Session + Print Edition (Marúbo `mzr`)

**Status:** Approved (owner, 2026-10-20).
**Scope:** Two deliverables sharing one data pipeline —
(A) a Dictionary session in the portal on port 8000, and
(B) a typeset, print-ready PDF edition of the whole dictionary.

**Governing records:** ADR-0001 (evidence-first), ADR-0021 (lexicon audit and consumer views),
ADR-0003 / ADR-0016 (CLDF interchange). This spec introduces **ADR-0027** (dictionary rendering
and print pipeline).

**Owners:** `exports/web/` (portal), `src/langpipe/lexicon/` (pipeline), `src/langpipe/lexicon/exporters/`
(print), `exports/mzr/formats/` (artifacts).

---

## 0. Decisions at a glance

| # | Question | Decision |
|---|---|---|
| D1 | Print depth | **Full scholarly dictionary**: headword, POS, Portuguese gloss, semantic domain, 1–2 attested examples with citation, status marker, guide words, A–Z index, numbered bibliography, front matter, reverse index. |
| D2 | Portal placement | **New top-level `Dicionário` tab**, a dedicated reading experience separate from the five LKB engineering workspaces. |
| D3 | Evidence visibility | **Simple by default, Expert toggle.** Simple = clean entry + status encoded as a 3px left-border color (no text). Expert = full provenance panel, toggled globally and persisted. |
| D4 | Shared data path | **One builder, two renderers.** A new `DictionarySessionBuilder` produces a normalized, sorted, display-ready entry list consumed by both the web session and the print template. |
| D5 | PDF engine | **WeasyPrint 70** (pure-Python, pip-installable, no TeX Live). Typst and LaTeX documented as alternatives in ADR-0027. |
| D6 | Print typeface | **Charis SIL 7.000** (OFL-1.1) for all dictionary text. Replaces Newsreader, which has no IPA coverage. |
| D7 | Print artifact layout | **One canonical `Dicionário Imprimível` card** in the Exports tab offering both print-ready HTML and generated PDF. The old printable HTML is regenerated by the new exporter; no stale artifact remains. |
| D8 | Dependency policy | `weasyprint` is a **core** dependency (pure Python wheels; keeps CI compiler-free), imported lazily inside functions, never at CLI module import time. |

## 1. Why this exists

The portal at `http://localhost:8000` is an **LKB engineering console**: master-detail audit
dossiers, a comparative matrix, an IGT corpus view, a synthetic laboratory, and a dataset
export hub. It is excellent for a linguist inspecting evidence. It is **not** a dictionary.

A community steward, a student, or a speaker looking up *waka* wants a page that reads like the
OED: the headword, the part of speech, the Portuguese equivalent, an attested sentence, and the
source it came from. They do not want a status dot, a valence field, and an audit banner.

The project is also evidence-first by construction (`AGENTS.md` invariant 3: *hypotheses are not
facts*; invariant 4: *lineage*). So the dictionary must **carry** the evidence without making a
casual reader wade through it. This spec resolves that tension with a three-tier disclosure
(D3).

A printed edition is separately required: the artifact that goes to a community, a school, or a
grant application is a **book**, and a book is typeset, paginated, and indexed — not a scrolling
web page or a markdown table.

### 2.2 PDF prior art

| Tool | Why considered | Outcome |
|---|---|---|
| **WeasyPrint 70** | Pure-Python wheels, no TeX Live. Full paged-media support **verified in source**: `string-set`, `string()`, `target-counter()`/`target-counters()`, `position: running()`, `@page` margin boxes, multi-column with `column-rule`, PDF outlines, `--pdf-variant=pdf/a-2b`. | **Adopted** (D5). |
| **Typst 0.15** | Sub-second compile, single binary, excellent default typography, `smallcaps`, `outline`, `bibliography`. | **Rejected for now**: the `columns` container is **not height-balanced** (per Typst docs), which is visible at every letter boundary in a two-column dictionary. ### 2.3 Typography conventions (the "real dictionary" feel)

Source: the OED's own *Guide to the dictionary*
(https://premium.oxforddictionaries.com/fr/mots/guide-to-the-dictionary), Wiktionary's `<pos>`
model, Béjoint's macrostructure/microstructure distinction, and Luna's *Clearly defined continuity
and innovation in the typography of English dictionaries*
(https://typography.network/wp-content/uploads/2024/04/Luna_TyPp_4_Clearly_defined_continuity_and_innovation_in_the_typography_of_English_dictionaries.pdf).

- **Entry structure**: headword → pronunciation → POS → senses → examples → cross-references.
- **Guide words**: the running head shows the first and last headword on the page (the Overleaf
  *Dictionary template*, CC BY-NC-SA 3.0, does exactly this).
- **Small caps** for POS and usage labels; the *Indexer* typographic note recommends
  letter-spacing small caps at least one unit.
- **Hanging indents** for sense lines; **one entry = one block**, never split across a column break.
- **Frequency banding**: high-attestation entries get more examples and space; low-attestation
  entries are compressed. Banding here uses **this repository's own attestation counts**, not an
  external frequency list — the language has no large corpus. Academic caution: word *frequency*
  is a poor proxy for lexical sophistication (Kyle, Crossley & Berger 2018), so bands are driven by
  evidence density, which is the honest signal available here.

### 2.4 Font

**Charis SIL 7.000** (OFL-1.1, https://github.com/silnrsi/font-charis). **Verified by parsing the
shipped font binary with fontTools:** full IPA block (U+0250–02AF) present, all Marúbo diacritics
present (`ẽ` U+1EBD, `ĩ` U+0129, `ã`, `õ`), real `smcp` small-caps feature present, `c2sc`,
`onum`, `locl`. Verified in WeasyPrint: embeds as a subset with `Identity-H` encoding, all
diacritics and IPA round-trip through `pdftotext`.

**TeX Gyre Pagella is disqualified** for any IPA-adjacent text — the font binary was parsed and
**269 of 271** IPA codepoints are missing. Newsreader, the typeface the current exporter uses, has
**no IPA coverage at all**.

### 2.5 Evidence disclosure — the design problem specific to this project

Modelled on the real problem articulated in
https://github.com/ericsocrat/decision-os/issues/114: *"Without visual confidence indicators,
users may trust estimated data as much as verified data."* The proposed remedy there — a small
badge with three visual states plus a tooltip and a "show only high-confidence" filter — is
adopted in adapted form (D3).

## 3. Architecture

```
exports/mzr/dictionary.json                    ← canonical export, immutable
        │
        ▼
  LexiconView  (existing; view = clean | names | quarantine | all)
  src/langpipe/lexicon/audit/view.py:58
        │
        ▼
  NEW  DictionarySessionBuilder
  src/langpipe/lexicon/dictionary/session.py
        │  produces: sorted, normalized, display-ready entries + facets + stats
        │
        ├──────────────────────────────┬───────────────────────────────┐
        ▼                              ▼                               ▼
  exports/web/dictionary_data.json   PrintableDictionaryExporter v2   /api/dictionary/session
  (compact static payload)          src/langpipe/lexicon/exporters/   (server endpoint)
   web Dictionary tab                printable.py  (rewritten)
                                           │
                                           ▼
                              dictionary_mzr_printable.html
                                           │
                                           ▼  WeasyPrint 70
                              dictionary_mzr_printable.pdf
```

**D4 rationale — one builder, two renderers.** The failure mode this prevents: the web UI and
the PDF each re-deriving "what is a display entry", so the printed book and the screen disagree
about what a status is, how a gloss is joined, or whether an example is shown. A single builder
means the two surfaces cannot drift. The builder is also the single place where the
**normalized search key** is computed, so the A–Z bucketing bug (below) cannot recur in the PDF
merely because the web fixed it.
### 3.1 Module boundaries

| Module | Responsibility | Must NOT |
|---|---|---|
| `langpipe/lexicon/dictionary/session.py` | Build the display-ready entry list, facets, and stats from a `LexiconView`. Pure function over dicts. | Touch the web, the filesystem, or the network. |
| `langpipe/lexicon/exporters/printable.py` | Render the print template (HTML+CSS) from session entries. | Re-derive entry semantics; re-read `dictionary.json`. |
| `langpipe/lexicon/exporters/pdf.py` | Drive WeasyPrint over the print template. | Contain layout or field logic. |
| `exports/web/server.py` | Expose the session payload and the print endpoint. | Contain field logic. |
| `exports/web/index.html` | Render the Dictionary tab. | Re-implement normalization, bucketing, or status semantics. |

## 4. Deliverable A — the Dictionary session

### 4.1 Layout

A dedicated reading view, distinct from the LKB console's master-detail:

```
┌──────────────────────────────────────────────────────────────────────┐
│  Dicionário Marúbo ⇄ Português        [ Simple | Expert ]  [ ⎙ PDF ] │
├────────────┬─────────────────────────────────────────────────────────┤
│ A B C D E… │                                                         │
│ ─────────  │   ẽa  PRON.  eu                                        │
│ (filtros)  │   ─────────────────────────────────────                 │
│  classe    │   Ãatõ vero wetsatakĩ mia ãwẽ oĩa miãromara ano …       │
│  domínio   │   "E viu em visão que um homem chamado Ananias …"      │
│  evidência │   (Act 9:12)                                           │
│ ─────────  │                                                         │
│  resultados│   ─────────────────────────────────────                 │
│  ẽa  eu    │   [Simple: 3px status border on the left]              │
│  mia  você │   [Expert: provenance panel below]                      │
│  nukẽ  nós │                                                         │
└────────────┴─────────────────────────────────────────────────────────┘
```

- **Left rail (280px)**: A–Z index strip, facet filters, live result list.
- **Right (fluid)**: the entry, typeset as a dictionary page.

### 4.2 Entry anatomy

**Simple view (default).**

```
ẽa   pron.   eu
     Ãatõ vero wetsatakĩ mia ãwẽ oĩa miãromara ano tachikaĩki mĩ …
     "E viu em visão que um homem chamado Ananias entrava, e lhe impunha a mão…"
     (Act 9:12)
```

- Headword: Marúbo form, large, in the display serif.
- POS: small-caps label (`PROPRON.`, `VERB.`, `NOM.`, `ADJ.`, `ADV.`, `NUM.`).
- Gloss: the Portuguese equivalent(s), joined with `; ` when there are several.
- Example: the attested Marúbo sentence, italic.
- Free translation: the Portuguese rendering, in quotation marks.
- Citation reference: `(Act 9:12)` — the source_ref of the first citation.

**Expert view** adds a provenance panel beneath the entry:

- Status chip with the exact state name (`candidate` / `supported` / `validated`).
- Confidence value and its provenance.
- Semantic domain, valence, inalienability.
- Audit flags and reasons (ADR-0021).
- The full `provenance` string (e.g. `Costa (1993, 2000) [ASJP]; ex: ẽa / 3a`).
- All citations, not just the first.
- Related-entry link when `audit.related_entry` is set (e.g. `berequiasnẽ` → `berequias`).

### 4.3 Evidence disclosure — three tiers (D3)

1. **Simple (default).** Headword, POS, gloss, example, citation ref. Status is encoded as a **3px
   left-border color** on the entry — no text, no badge. A reader who does not care about
   evidence is not interrupted; a reader who notices the color learns something.
2. **Hover / focus.** A one-line source strip appears: `validado · 3 atestações · Costa (2002)`.
   No modal, no panel.
3. **Expert toggle.** A switch in the Dictionary tab header, persisted in `localStorage`, plus
   `?expert=1` as a shareable override. Reveals the full provenance panel.

Additionally, a **facet filter** "somente validados" (show only validated entries) is available
in Simple view. This is the honest analogue of "show only high-confidence scores" — a researcher
can get a defensible subset without a mode switch.

**Accessibility:** status is encoded by **shape and colour together** (border style + colour), not
colour alone. The border carries a distinct weight per status so it is legible in greyscale.

### 4.4 Search

The current implementation (`exports/web/index.html:2525-2537`) does `toLowerCase()` +
`includes()` over the full list on every keystroke. It is neither accent-insensitive nor
ranked. The new implementation:

- **Two keys per entry.** `headword` (exact, marks intact) for display and exact matching;
  `searchKey` (NFD-normalized, combining marks stripped) for matching. A user typing `coracao`
  matches `coração`; a user typing `ẽa` matches `ẽa`. Marúbo's `ẽ/ĩ/ã/õ` are preserved for
  display and never conflated in the stored key.
- **Ranking.** Exact headword match → exact gloss match → prefix match on `searchKey` → substring.
  Ranking is by attestation count, then alphabetically (the same ordering the reverse index
  already uses, `src/langpipe/lexicon/reverse.py:265`).
- **Bidirectional.** One index serves both Marúbo→Portuguese and Portuguese→Marúbo. Both
  languages are Latin-script, so script detection is impossible; an **explicit direction toggle**
  is used, defaulting to Marúbo→Portuguese, with the reverse direction seeded from the existing
  `dictionary.reverse.json` index.
- **Keyboard.** `/` focuses search (already present at `index.html:1333` and `index.html:3128` —
  preserved). `↑`/`↓` move the highlighted result, `Enter` opens it, `Esc` clears and returns
  focus. The search box captures keystrokes only while focused.
- **Deep links.** `?q=<query>&dir=<mzr-por|por-mzr>` — shareable and citable.

### 4.5 A–Z index

The A–Z strip buckets by the **normalized** key, so `á` files under `A`, not under a separate `Á`
bucket. The current `printable.py:50` has exactly this bug (`first_char = hw[0].upper()`), and it
is fixed in the shared builder so both surfaces are correct.

Empty letters are shown disabled. The strip is keyboard navigable.

## 5. Deliverable B — the print edition

### 5.1 Pipeline

`DictionarySessionBuilder` → `PrintableDictionaryExporter` (HTML+CSS) → **WeasyPrint 70** → PDF.

Both the HTML and the PDF are written to `exports/mzr/formats/`, next to the existing
`dictionary_mzr.lift` and `formats/cldf/`.

### 5.2 Typeface (D6)

**Charis SIL 7.000**, self-hosted via `@font-face` pointing at a `fonts/` directory inside the
export. Not fetched from a CDN at render time — the PDF build must be reproducible and
offline-capable. Regular, Bold, and Italic are bundled; the OFL-1.1 licence text ships alongside.

The font is embedded in the PDF automatically by WeasyPrint as a subset.

### 5.3 Page structure

**Front matter**
1. Title page — language, family, glottocode, territory, contact language, entry count, edition date.
2. Preface — what the dictionary is, the evidence-first methodology, what `candidate` /
   `supported` / `validated` mean, and how to read a status marker.
3. Morpheme table — the 12 morphemes already described in `exports/mzr/dictionary.md` §1.
4. Reverse index (Portuguese → Marúbo) — from `dictionary.reverse.json`.

**Body**
5. A–Z dictionary, two columns with a hairline rule, letter sections with a display heading.
6. Guide words in the running head (first and last headword on the page).
7. Numbered bibliography at the end — citations render as superscript markers keyed to a
   de-duplicated source list, replacing the per-entry red-border block.
8. Back matter: semantic-domain index.

### 5.4 WeasyPrint features used (all verified working)

| Feature | CSS | Purpose |
|---|---|---|
| Guide words | `string-set: gw content();` + `@top-left { content: string(gw, first); }` / `@top-right { content: string(gw, last); }` | Running head, first/last headword |
| Folios | `@bottom-center { content: counter(page); }` | Page numbers |
| Cross-references | `a::after { content: target-counter(attr(href url), page); }` | "cf. *poku*, p. 42" |
| Two columns | `column-count: 2; column-rule: 0.5pt solid …` | Classic dictionary layout |
| Entry integrity | `break-inside: avoid` | An entry never splits across a column |
| Small caps | `font-variant: small-caps` | POS and usage labels (Charis has real `smcp`) |
| Hyphenation | `hyphens: auto` + `lang="pt-BR"` | Narrow justified columns without rivers |
| Orphan control | `break-after: avoid` on letter headings | A letter heading never orphans |

**Verification note (empirical, performed during design):** WeasyPrint's `position: running()`
and `:first-of-type` approaches to guide words **do not work** — the running head stayed empty.
`string-set: gw content()` with `string(gw, first|last)` **does** work, confirmed by rendering
to PNG and inspecting the page image. The implementation MUST use the working form; the failing
forms must not be reintroduced.

### 5.5 Correctness fixes over the current exporter

The existing `src/langpipe/lexicon/exporters/printable.py` is a working but rough draft. The
rewrite fixes:

1. **Letter bucketing** — normalized key, so `á` files under `A` (current: `hw[0].upper()`).
2. **Typeface** — Charis, not Newsreader (no IPA).
3. **Guide words** — absent today.
4. **Citations** — a numbered bibliography instead of a repeated red-left-border block.
5. **Sense structure** — hanging indents and a gloss line, not a single run-on line.
6. **Front and back matter** — absent today.
7. **Render time** — the current export takes **80s** for 43 pages. Restructured (local fonts,
   flattened column containers, `hyphens: auto`) the same content renders in **~7s**; the
   per-entry citation blocks are the dominant cost, so the numbered-bibliography treatment
   brings the full scholarly edition into a target of **<30s**.

### 5.6 PDF output options

- Page size A4 portrait, 20/15mm margins.
- PDF outline (bookmarks) per letter section — WeasyPrint generates these from headings.
- Internal hyperlinks from the guide words and cross-references.
- `--pdf-variant=pdf/a-2b` is available for an archival variant; the default artifact stays a
  standard PDF for maximum reader compatibility.

## 6. Server changes

`exports/web/server.py` gains two endpoints:

| Endpoint | Method | Behaviour |
|---|---|---|
| `/api/dictionary/session` | GET | Returns the session payload: entries, facets, stats, direction indices. Cached in memory; invalidated when the source export's mtime changes. |
| `/api/dictionary/print` | POST | Renders the print edition and returns the artifact path for download. Body: `{lang, view, format}`. |

**Bug fix (mandatory, in scope):** the Exports tab links to `/formats/dictionary_mzr.lift`,
`/formats/cldf/Dictionary-metadata.json`, and `/formats/dictionary_mzr_printable.html`, but
`server.py:38` serves **only** `exports/web/`. **All three links currently return 404.** The new
print edition's link MUST work. Options, in order of preference:

1. Serve `exports/mzr/formats/` under a `/formats/` path by overriding the static root, and
2. add a route for the PDF under `/api/dictionary/print` output.

The fix is verified by a request-level test asserting HTTP 200 for each advertised artifact.

### 6.1 The `Dicionário` tab

A new top-level nav tab in `exports/web/index.html`, alongside `Léxico & Dicionário`,
`Matriz Comparativa`, `Corpus & IGT`, `Laboratório Sintético`, and `Datasets & Exportações`.
It opens **active by default** when the portal is first loaded with no hash, since it is now the
primary human-facing surface — the LKB console remains one click away.

The tab carries its own header: the dictionary title, the **Simple/Expert** switch, the
**direction toggle**, and the **⎙ PDF** button.

## 7. Governance fit

| Invariant | How the design satisfies it |
|---|---|
| **2** Observation ≠ inference | The Simple/Expert split never lets a `candidate` read as settled; the status is always *representable*. |
| **3** Hypotheses are not facts | Expert view shows the exact state name; Simple view shows only a color, which the preface explains. Machine confidence never promotes an entry. |
| **4** Lineage | Provenance string and full citation list travel from `dictionary.json` into both the web entry and the printed entry. |
| **7** Ambiguity preserved | Multiple glosses render as a list, not a collapsed string; multiple citations are all shown in Expert view. |
| **10** No unauthorized egress | The PDF is rendered locally by WeasyPrint. **No font, entry, or example is sent to any third-party API.** The existing `index.html` loads Google Fonts at runtime; the print path must not depend on that. |
| **11** Persisted format changes | New derived artifacts under `exports/mzr/formats/`. Tests and documentation land with them. |
| **12** ADRs | **ADR-0027** records the PDF engine choice, the typeface choice, and the Typst/LaTeX alternatives. |

**Language isolation (AGENTS.md):** no Marúbo-specific rule may appear in generic pipeline code.
The builder is parameterized by language code and contact language, exactly like
`src/langpipe/lexicon/reverse.py` already is. Marúbo-specific facts (glottocode, territory,
morpheme table) are **data**, read from the export, not code.

## 8. Testing plan

### 8.1 Unit — `tests/unit/test_lexicon_dictionary_session.py` (new)

- Builder output shape: required keys on every entry.
- **Normalized search key**: `coracao` matches `coração`; `ẽa` does not collide with `ea`.
- Sorting is stable and locale-correct for the Marúbo diacritics.
- **A–Z bucketing**: `á` lands in `A`, not `Á`.
- Status is preserved exactly; `candidate` is never rendered as `validated`.
- Multiple glosses and multiple citations are preserved (not collapsed).
- Facet counts match the entry lists.
- Ambiguity: an entry with 2 glosses yields 2 gloss items.

### 8.2 Unit — `tests/unit/test_lexicon_exporters.py` (extended)

- The print HTML contains the guide-word CSS (`string-set`, `string(gw, first)`, `string(gw, last)`).
- The print HTML contains a `@font-face` for Charis and **no** reference to Newsreader.
- The print HTML contains `target-counter` for cross-references.
- Every session entry appears **exactly once** in the print output.
- Letter sections are bucketed by the normalized key.
- The numbered bibliography de-duplicates sources correctly.

### 8.3 PDF smoke test (new)

Render the 892-entry clean view and assert:

- the PDF file exists and is non-empty;
- `pdffonts` reports **Charis** embedded;
- `pdftotext` output contains a known headword with its diacritics intact (e.g. `ẽa`, `wẽstisẽ`) —
  this is the "no `.notdef` glyphs" check;
- the page count is within the expected band (a regression guard against layout collapse);
- render completes under the performance target.

The test must be skipped, not failed, when the optional PDF toolchain is absent — CI must stay
compiler-free and dependency-light.

### 8.4 Server tests (new)

- `GET /api/dictionary/session` returns HTTP 200 and a well-formed payload.
- The session payload's entry count matches the source export.
- `POST /api/dictionary/print` returns a path to an existing PDF.
- **Every artifact link advertised in the Exports tab returns HTTP 200** (the current 404 bug).

### 8.5 Regression

Existing `tests/unit/test_lexicon_exporters.py` assertions must continue to hold where the
behavior is unchanged, and be updated where D1/D6 deliberately changed the output.

## 10. Out of scope (deferred, with reasons)

| Item | Why deferred |
|---|---|
| **Offline PWA** (service worker + manifest) | The prior art shows it is straightforward (~40 lines, no bundler) and valuable for a community dictionary. It is a *separate* deliverable from this spec, because it changes the deployment surface (requires HTTPS or localhost) and deserves its own design. |
| **`clld` app** | The scholarly layer could be a `clld` app over the existing CLDF export. Valuable, but a distinct product from the community-facing portal, and a much larger dependency surface. The **CLDF data contract** is already the interchange format. |
| **Typst print edition** | Recorded in ADR-0027 as the alternative for a community member who wants to typeset their own edition. |
| **Audio** | The repository contains **no** audio files (verified). A dictionary for a spoken language wants pronunciation, but there is no audio to link. Phonetic transcription is likewise absent from the data (the orthography is `ẽ/ĩ/ã/õ`, not IPA). **This is a data gap, not a UI gap** — noted so it is not mistaken for a missing feature. |
| **Reverse PDF volume** | The reverse index is included as front matter in the single volume. A separate bound reverse volume can follow if demand appears. |

## 11. Open questions

- **Should the PDF include entries from the `quarantine` view?** Default: **no** — the clean view
  is the defensible subset. The reverse index and the onomasticon are already separate views in
  the portal. Noted for the owner if a community edition wants the full 1,099.
- **Print run and page size.** A4 is assumed. A community print run in Brazil might want
  15×21cm or a saddle-stitched booklet format. A4 is a safe default; the template's page box is
  a single CSS variable.
- **Romanization / respelling.** The Marúbo orthography uses `ẽ ĩ ã õ` and a `w`/`y` distinction.
  Whether the printed edition should carry a short orthography note explaining the nasal diacritics
  and the `w`/`y` contrast is an open question for the community editor.
